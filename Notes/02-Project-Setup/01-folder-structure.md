# Project Setup — Part 1 of 3: Folder Structure

The folders and files generated by `npm init playwright@latest` (with TypeScript, `tests` folder and GitHub Actions workflow selected).

---

## 1. Project Tree

```
my-project/
├── .github/
│   └── workflows/
│       └── playwright.yml       ← GitHub Actions workflow (CI)
├── node_modules/                ← installed packages (created by npm install)
├── tests/
│   └── example.spec.ts          ← sample test file
├── .gitignore                   ← files/folders Git should not track
├── package.json                 ← project info + packages
├── package-lock.json            ← exact installed package versions
└── playwright.config.ts         ← Playwright settings
```

**Created later, when you run tests** (listed in `.gitignore`, so not committed):
```
├── test-results/                ← output of each test run (traces, screenshots)
└── playwright-report/           ← HTML report (open with npx playwright show-report)
```

---

## 2. What Each Item Is For

| Item | What it is for | Commit to Git? |
|------|----------------|----------------|
| `.github/workflows/playwright.yml` | Only created if you chose **Yes** for the GitHub Actions question. Runs the tests on GitHub on every push / pull request to `main` or `master` | ✅ Yes |
| `node_modules/` | The installed packages. Re-created any time with `npm install` | ❌ No |
| `tests/` | Where test files go (named after your answer to the tests folder question). Playwright looks here because of `testDir: './tests'` in the config | ✅ Yes |
| `tests/example.spec.ts` | Sample test. Test files end with **`.spec.ts`**. It opens https://playwright.dev/ in a browser, so it is a UI test, not an API test | ✅ Yes |
| `.gitignore` | Tells Git which files/folders to ignore | ✅ Yes |
| `package.json` | Project name, scripts and the packages it needs. See [Part 3](03-package-json.md) | ✅ Yes |
| `package-lock.json` | Locks the exact versions of every installed package, so everyone gets the same ones | ✅ Yes |
| `playwright.config.ts` | How tests run: folder, browsers, reporter, retries, etc. See [Part 2](02-playwright-config.md) | ✅ Yes |
| `test-results/` | Output from the last test run | ❌ No |
| `playwright-report/` | The HTML report from the last test run | ❌ No |

---

## 3. `.gitignore` Entries

| Entry | What it ignores |
|-------|-----------------|
| `node_modules/` | Installed packages |
| `/test-results/` | Test run output |
| `/playwright-report/` | HTML report |
| `/blob-report/` | Report data used when merging reports |
| `/playwright/.cache/` | Playwright cache |
| `/playwright/.auth/` | Saved login/auth state (may contain secrets) |

---

## 4. GitHub Actions Workflow (`playwright.yml`) Steps

| Step | What it does |
|------|--------------|
| `on: push / pull_request` → `main`, `master` | When the workflow runs |
| `runs-on: ubuntu-latest` | Runs on a Linux machine provided by GitHub |
| `actions/checkout@v4` | Downloads the repository code |
| `actions/setup-node@v4` with `lts/*` | Installs the latest LTS Node.js |
| `npm ci` | Installs the exact packages from `package-lock.json` |
| `npx playwright install --with-deps` | Installs the browsers and the system libraries they need |
| `npx playwright test` | Runs the tests |
| `actions/upload-artifact@v4` | Saves `playwright-report/` for 30 days so you can download it from GitHub |

# Project Setup — Part 2 of 3: playwright.config.ts

`playwright.config.ts` controls **how** Playwright runs the tests. This page explains each setting in the default config generated by `npm init playwright@latest`.

Official docs: https://playwright.dev/docs/test-configuration

---

## 1. File Structure

```typescript
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  // top-level settings: how tests run
  use: {
    // shared settings for every test
  },
  projects: [
    // browsers / configurations to run the tests in
  ],
});
```

- **`defineConfig`** wraps the settings and gives autocomplete and type checking in VS Code.
- **`devices`** is a list of ready-made browser/device settings (e.g. `Desktop Chrome`).

---

## 2. Top-Level Settings

| Setting | Default value | What it means |
|---------|---------------|---------------|
| `testDir` | `'./tests'` | Directory with the test files. |
| `fullyParallel` | `true` | All tests in all files run in parallel. |
| `forbidOnly` | `!!process.env.CI` | Exit with an error if any test is marked `test.only`. Only on CI, so a forgotten `test.only` can't silently skip the other tests there. |
| `retries` | `process.env.CI ? 2 : 0` | Maximum retry attempts per failing test: **2 on CI, 0 locally**. |
| `workers` | `process.env.CI ? 1 : undefined` | Maximum number of worker processes running tests at the same time: **1 on CI**, **automatic locally**. |
| `reporter` | `'html'` | Creates the HTML report in `playwright-report/`. Open it with `npx playwright show-report`. |

> **`process.env.CI`**: CI services like GitHub Actions set an environment variable called `CI`. `process.env.CI ? A : B` means "A on CI, B on my machine". `!!` turns the value into `true`/`false`.

---

## 3. `use` — Shared Settings for All Tests

| Setting | Default value | What it means |
|---------|---------------|---------------|
| `baseURL` | commented out | Base URL, so tests can use short paths like `/users` instead of the full URL. |
| `trace` | `'on-first-retry'` | Collect a trace when retrying a failed test. Open it from the HTML report to see what happened step by step. |

---

## 4. `projects` — Browsers

| Project name | Device settings |
|--------------|-----------------|
| `chromium` | `devices['Desktop Chrome']` |
| `firefox` | `devices['Desktop Firefox']` |
| `webkit` | `devices['Desktop Safari']` |

Commented out (not active): Mobile Chrome, Mobile Safari, Microsoft Edge, Google Chrome.

**Every test runs once per project**, so with 3 projects each test runs 3 times.

Run one project only:
```bash
npx playwright test --project=chromium
```

---

## 5. Commented-Out Sections

| Section | What it is for |
|---------|----------------|
| `dotenv` lines at the top | Load variables (e.g. API URL, tokens) from a `.env` file. Needs the `dotenv` package, which is not installed by default. |
| `webServer` | Start a local server (e.g. `npm run start`) before the tests run. |

---

## 6. Settings for API Testing

From the official API testing docs (https://playwright.dev/docs/api-testing):

- **No browser is required** for API tests. Requests are sent directly from Node.js using the **`request`** fixture.
- The `request` fixture uses the settings in `use`, so API details are set **once** in the config.

| Setting | What it does |
|---------|--------------|
| `baseURL` | The API's address. Tests then use short paths, e.g. `request.get('/users')`. |
| `extraHTTPHeaders` | Headers sent with **every** request, e.g. `Accept` or `Authorization`. |

**Official example:**
```typescript
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    baseURL: 'https://api.github.com',
    extraHTTPHeaders: {
      'Accept': 'application/vnd.github.v3+json',
      'Authorization': `token ${process.env.API_TOKEN}`,
    },
  }
});
```

> `process.env.API_TOKEN` reads the token from an environment variable, so the secret is not written in the code.
